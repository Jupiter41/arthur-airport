# Pluggable Data Source Adapter System

## Overview

The Arthur Airport Digital Twin supports multiple data sources for each domain service.
Each service can consume data from either the simulation engine or real-world APIs,
selectable at runtime via REST endpoints or environment variables.

## Architecture

```
┌─────────────────────────────────────────────────────────┐
│                    API Gateway                            │
│  GET /api/v1/data-sources  →  aggregate source status    │
└───────────┬───────────────────────────────────────────────┘
            │
    ┌───────┴───────┐
    │  Per-service  │
    │ /source GET   │  ← current source config
    │ /source POST  │  ← runtime switch
    └───────────────┘
            │
    ┌───────┴───────────────────────────────────┐
    │              Service Consumer              │
    │                                           │
    │  ┌──────────┐  ┌──────────┐  ┌────────┐  │
    │  │Simulated │  │Historical│  │  Live  │  │
    │  │ Provider │  │ Provider │  │Provider│  │
    │  └────┬─────┘  └────┬─────┘  └───┬────┘  │
    │       │              │            │       │
    │       └──────────────┴────────────┘       │
    │                     │                     │
    │       ┌─────────────▼──────────────┐      │
    │       │  Canonical Event / Entity  │      │
    │       │  (same Kafka + Neo4j shape)│      │
    │       └────────────────────────────┘      │
    └───────────────────────────────────────────┘
```

## Key Principle

**Downstream services remain unchanged.** Any source adapter publishes the same
canonical Kafka events and writes the same Neo4j entity shape. The adapter is a
thin translation layer at the system edge.

## Shared Data Source Framework

All services use a shared `DataSourceRegistry` and `DataSourceAdapter` protocol
from `services/_common/data_sources.py`. This provides:

- **`DataSourceAdapter` Protocol** — Interface all adapters must implement:
  `source_id`, `label`, `is_loaded`, `load()`
- **`DataSourceRegistry`** — Per-theme registry for registration, switching, listing
- **`SimulatedSourceAdapter`** — Default adapter for simulation-generated data

### Quick Integration Example

```python
from _common.data_sources import DataSourceRegistry, SimulatedSourceAdapter

# 1. Create registry for your theme
registry = DataSourceRegistry("weather", env_var="WEATHER_SOURCE", default="simulated")

# 2. Register adapters
registry.register(SimulatedSourceAdapter())
registry.register(MyHistoricalAdapter())
registry.register(MyLiveAdapter())

# 3. Switch at runtime
result = registry.switch("historical")  # → {"previous": "simulated", "active": "historical"}

# 4. Get unified info for REST API
info = registry.info()  # → {"theme": "weather", "active_source": "historical", "available": [...]}
```

### Adapter Wrapper Pattern

Existing service-specific adapter classes (e.g. `HistoricalMetarSource`, `BTSPassengerSource`)
are wrapped in thin adapter classes that implement the `DataSourceAdapter` protocol while
delegating lifecycle management to the existing consumer state:

```python
class _HistoricalAdapter:
    source_id = "historical"
    label = "Iowa State Mesonet CSV"

    @property
    def is_loaded(self) -> bool:
        return _state._historical is not None and _state._historical.is_loaded

    def load(self) -> int:
        return 0  # managed by switch_weather_source()
```

### Step 2: Register in Kafka Consumer

Add source selection logic in the service's consumer dispatch:

```python
# In services/passenger-service/kafka/consumer.py

class ConsumerState:
    def __init__(self):
        self.passenger_source = os.getenv("PASSENGER_SOURCE", "simulation").lower()
        self._bts: BTSPassengerSource | None = None

        if self.passenger_source == "bts_historical":
            csv_path = os.getenv("PASSENGER_BTS_FILE", "/app/data/bts/T100_2023.csv")
            self._bts = BTSPassengerSource(csv_path)
            count = self._bts.load()
            if count == 0:
                logger.warning("BTS data empty — falling back to simulation")
                self.passenger_source = "simulation"

    async def _process_tick(self, sim_time: str):
        if self.passenger_source == "bts_historical":
            await self._apply_bts_data(sim_time)
        else:
            await self._apply_simulated_flow(sim_time)
```

### Step 4: Expose Source Endpoints

```python
# In services/passenger-service/routers/passengers.py

@router.get("/passengers/source")
async def passenger_source():
    """Current passenger data source configuration."""
    from kafka.consumer import get_state
    state = get_state()
    return {
        "source": state.passenger_source,
        "available": ["simulation", "bts_historical"],
    }

@router.post("/passengers/source")
async def switch_passenger_source(body: dict):
    """Switch passenger source at runtime."""
    from kafka.consumer import switch_source
    return switch_source(body.get("source"), body.get("csv_path"))
```

## Runtime Source Switching

Sources can be switched at runtime via:

1. **REST API**: `POST /api/v1/weather/source` with `{"source": "live", "live_icao": "EGLL"}`
2. **Dashboard UI**: Data Sources page → click source button
3. **Environment variable**: Set at container startup (requires restart)

## Data Format Contracts

All adapters must output data conforming to:

- **Kafka events**: Schema defined in `docs/architecture/EVENT_BUS.md`
- **Neo4j entities**: Schema defined in `docs/architecture/DATA_MODEL.md`
- **REST responses**: Pydantic models in each service's `models/` directory
